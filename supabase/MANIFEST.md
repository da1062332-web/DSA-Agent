## Rules

1. A merged migration is never edited. Corrections are new files in the owner's range.
2. Only the owning module writes migrations for its tables. Referencing another module's table by FK is allowed; altering it is not.
3. A new number needs a manifest PR.
4. CI applies all migrations to an empty database (`supabase db reset`), then runs the RLS lint and the other §8 checks.
5. Roles: migrations run as `postgres`. The API logs in as `dsa_api` (member of `dsa_app`, NOBYPASSRLS, not the owner, no DELETE grants). `dsa_api` is created **outside** migrations, with a password from the secret store (REL-001):

   ```sql
   CREATE ROLE dsa_api LOGIN PASSWORD '<secret>' NOBYPASSRLS IN ROLE dsa_app;
   ALTER ROLE dsa_api SET search_path = app, extensions;
   ```
