# Audit migration batch: runbook (0066, 0069 to 0084)

Status: **prepared and rehearsed, not applied.** Nothing in this folder has been run against hosted. Every command below that writes is
yours to run, after you approve. The API on `beta` already uses these tables; until they exist, the endpoints built in the 2026-10-19 audit
follow-up fail on hosted, and the worker logs one warning that 0069 is missing.

Rehearsal evidence: `apps/api/test/migration-audit-batch.int.spec.ts` (Testcontainers, PostgreSQL 16) builds a hosted-like database (every
migration up to 0068 except 0066, plus the hosted test fixtures) and shows:

- the preflight is read-only, every prerequisite passes, all 17 migrations are pending, and none is after the batch;
- for every migration: verify passes after apply; rollback restores the database exactly (columns, constraints, indexes, policies, triggers,
  function bodies, permissions, role grants, table and column privileges); verify then shows FAIL; running the rollback again changes nothing;
- the rollback guards refuse when data would be lost (a document type, tenant entitlements, a merged customer).

The scripts are generated by `generate.py` (`python tools/sql/audit-batch/generate.py tools/sql/audit-batch`); edit it, not the `.sql` files.

## Order

Apply in number order (`pending.mjs` does). 0066 is included because hosted's state is not recorded; the preflight skips it if
`lender_query` exists. Prerequisites checked by the preflight: 0050 platform realm, 0067 outbox relay, 0068 tenant feature flags, 0037
webhook tables, 0027 connectors.

## Commands

From the repository root, with the shared development project linked (`supabase/.temp/project-ref` = `mlpkwwhnagxzinaohdxg`):

```bash
# 1. Read-only: what is pending
npx supabase db query --linked -f tools/sql/audit-batch/preflight.sql

# 2. State backup first (docs/HOSTED_APPLY_CHECKLIST.md): the runner refuses without
#    ~/dsa-backups/audit-batch-<date>/state.sql

# 3. Apply: one migration at a time, verify after each, stop at the first problem (asks before writing)

# Back one out, if a verify fails or you change your mind (newest first)
npx supabase db query --linked -f tools/sql/audit-batch/<NN>.rollback.sql
```

After the batch: restart the API (the 0069 warning goes), update `docs/MIGRATION_MATRIX.md`, sign in once as a tenant admin and once as a
platform operator.
